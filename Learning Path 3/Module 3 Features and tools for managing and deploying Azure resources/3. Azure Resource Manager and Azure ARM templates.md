
- **Azure's deployment + management service**
- Management layer for **creating, updating, and deleting** Azure resources
- All Azure resource operations go through ARM

### Request Flow
1. Azure tool / API / SDK sends request
2. **ARM authenticates + authorizes**
3. ARM sends request to relevant Azure service
4. Azure service performs action

- Common API → consistent capabilities across tools

### ARM Benefits
- **Infrastructure as Code (IaC):** Declarative templates instead of manual configuration
- Manage/deploy/monitor resources as a **group**
- Consistent deployments across environments
- Define resource **dependencies**
- Native **RBAC** integration
- Apply **tags** for organization and cost reporting

### ARM Templates
- **JSON-based declarative** templates
- Define desired resource state
- ARM:
    - Validates template
    - Determines dependencies
    - Deploys resources in correct order
    - Deploys independent resources in parallel
- Can use PowerShell/Bash deployment scripts when required

**Benefits:**
- Declarative
- Repeatable
- Automatic orchestration
- Modular/reusable
- Extensible with deployment scripts

### Bicep
- **Declarative language** for Azure deployments through ARM
- Simpler and more concise than JSON ARM templates

**Benefits:**
- Supports current Azure resource types/API versions
- Easier syntax
- **Idempotent** → consistent deployments
- Automatic dependency/orchestration handling
- Modular through **Bicep modules**

### Key Distinction
- **ARM:** Deployment/management engine
- **ARM Templates:** JSON IaC format used by ARM
- **Bicep:** Simpler IaC language compiled/deployed through ARM
