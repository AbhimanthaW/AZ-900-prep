
- **Purpose:** Enforce and audit resource configuration compliance
- Evaluates resources against defined rules
- Can:
    - Detect noncompliant resources
    - Prevent noncompliant resources from being created
    - Automatically remediate some issues
    - Monitor configuration changes

### Policy Scope
- Policies can apply to:
    - Resource
    - Resource group
    - Subscription
    - Higher levels
        
- **Inheritance:** Policies assigned at a higher level automatically apply to child resources
    
### Policy Definitions

- Individual rules controlling/auditing configurations
- Built-in policies available for:
    - Storage
    - Networking
    - Compute
    - Security
    - Monitoring
- Policies evaluate **existing and newly created resources**
- Example: Restrict VM sizes during creation and resizing
    

### Remediation & Exceptions
- Some policies can automatically fix noncompliance
- Example: Automatically add missing `AppName` tag
- Resources can be configured as **exceptions**
    
### Azure Policy Initiatives
- **Initiative = group of related policies**
- Used to manage compliance toward a larger goal
- Example: **Enable Monitoring in Azure Security Center**
    - Monitor unencrypted SQL databases
    - Monitor OS vulnerabilities
    - Monitor missing endpoint protection
    - Contains **100+ policy definitions**

### AI-Assisted Changes
- Azure Policy still enforces standards when changes come from AI/Copilot/automation
- Can enforce:
    - Allowed locations
    - Required tags
    - Approved SKUs
    - Security baselines

### Azure DevOps
- Integrates with CI/CD pipelines
- Policies can apply during:
    - Pre-deployment
    - Post-deployment
