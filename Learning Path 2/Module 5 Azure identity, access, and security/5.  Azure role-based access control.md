**Core Concept**

- **Azure Role-Based Access Control (RBAC):** Manages access to cloud resources by implementing the **Principle of Least Privilege** (granting only the minimum access necessary for a task).

**Key Features**
- **Built-in & Custom Roles:** Roles group specific access permissions together to simplify access management for individuals or groups.
    
- **Allow Model:** Permissions are additive. If multiple roles grant different access rights (e.g., Read on one assignment and Write on another), both apply.
    
- **Management-Plane Enforcement:** Enforced strictly through **Azure Resource Manager (ARM)** across Portal, CLI, PowerShell, and SDKs. Does _not_ control data-plane or application-level security.
    
**Scopes & Inheritance Hierarchy**

Permissions assigned at a higher level automatically **inherit** down to all lower scopes.

```
Management Group  (Top level: multiple subscriptions)
└── Subscription  (Billing & boundary level)
    └── Resource Group  (Logical grouping of resources)
        └── Resource  (Single Azure asset)
```

| **Scope Level**      | **Description**                      | **Impact**                                                  |
| -------------------- | ------------------------------------ | ----------------------------------------------------------- |
| **Management Group** | Collection of subscriptions          | Applies to all underlying subscriptions and their contents. |
| **Subscription**     | Single Azure subscription            | Applies to all resource groups and assets within it.        |
| **Resource Group**   | Container for related resources      | Applies to all individual resources inside it.              |
| **Resource**         | Individual asset (e.g., VM, storage) | Restricts permissions strictly to that specific item.       |
