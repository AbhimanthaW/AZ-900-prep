**Microsoft Entra ID vs. Microsoft Entra Domain Services Overview**

**Microsoft Entra ID** is a modern, cloud-based identity and access management (IAM) service designed for cloud-native applications using modern protocols like OAuth 2.0, OpenID Connect, and SAML.

**Microsoft Entra Domain Services** provides managed domain services—such as domain join, Group Policy, LDAP, and Kerberos/NTLM authentication—without needing to deploy or manage Windows Server domain controllers in Azure.

**Key Comparison**

| **Feature / Aspect**    | **Microsoft Entra ID**                                       | **Microsoft Entra Domain Services**                                          |
| ----------------------- | ------------------------------------------------------------ | ---------------------------------------------------------------------------- |
| **Primary Focus**       | Cloud-native identity & access management                    | Managed Active Directory Domain Services (AD DS) in the cloud                |
| **Supported Protocols** | OIDC, OAuth 2.0, SAML, WS-Federation                         | Kerberos, NTLM, LDAP, LDAPS, Group Policy                                    |
| **Target Workloads**    | Cloud apps (SaaS, M365, Azure portal, custom web apps)       | Legacy on-premises applications lifted & shifted to Azure VMs                |
| **Domain Join & GPO**   | Supports Entra Join / MDM (e.g., Intune); **No GPOs**        | Supports traditional Active Directory domain join & **Group Policy (GPOs)**  |
| **Underlying Infra**    | Fully managed global cloud directory                         | Automates 2 managed domain controllers (replica set) in an Azure VNet        |
| **Synchronization**     | Syncs from On-Premises AD via Entra Connect (bi-directional) | **One-way sync** from Microsoft Entra ID $\rightarrow$ Entra Domain Services |

**Primary & Secondary Region Redundancy in Entra Domain Services**

Because Microsoft Entra Domain Services deploys actual domain controllers behind the scenes into an Azure Virtual Network (VNet), maintaining domain availability across multiple geographic locations works as follows:

1. **Primary Region (Replica Set 1):**
    - When created, Entra Domain Services provisions a **replica set** consisting of **two managed Windows Server domain controllers** within your primary region's virtual network.
    - Microsoft handles DC maintenance, OS patching, backups, and disk encryption automatically.
        
2. **Secondary Region (Additional Replica Sets):**
    - To guard against regional outages or to support workloads deployed in multiple Azure regions, you can add **additional replica sets** in secondary regions.
    - All replica sets belong to the same managed domain, share the same directory data, and synchronize changes automatically across regions.
    - In the event of a regional outage in your primary region, applications in secondary regions can continue authenticating against their local replica set.
