**Core Concept**
- **Conditional Access:** Microsoft Entra ID’s Zero Trust policy engine that uses if-then logic to allow, deny, or step-up access based on identity signals.

**How It Works (Signal → Decision → Enforcement)**

1. **Signals (Input):** Evaluates context at sign-in (User identity/role, network/IP location, device compliance state, target app, and real-time risk level).
    
2. **Decision (Logic):** Processes signals against configured policies to determine appropriate access requirements.

3. **Enforcement (Outcome):** Executes the decision (e.g., Allow full access, Block access, or Require MFA/password change).
    
**Common Use Cases**
- **Require MFA:** Mandatory for privileged admin roles or connections from untrusted networks.
    
- **Require Managed Devices:** Restrict sensitive app access strictly to compliant or Entra hybrid-joined devices.
    
- **App Restrictions:** Limit access exclusively through approved client applications or session-monitored browsers.
    
- **Block Untrusted Sources:** Automatically block sign-in attempts from unexpected geographic locations or high-risk IP addresses.
