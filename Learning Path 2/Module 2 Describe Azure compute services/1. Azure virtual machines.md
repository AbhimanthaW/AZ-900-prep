virtualised servers in Azure as IaaS

- total control over the operating system (OS).
- ability to run custom software.
- use custom hosting configurations.

no need to buy & maintain physical server hardware
- manage patching, updates, and configuration

**when to use VMs**
- **Testing and development**. Create different OS and app configurations quickly, then remove the VM when testing is complete.
- **Cloud application hosting**. Run applications in Azure and scale capacity up or down as demand changes.
- **Datacenter extension**. Extend an on-premises network into Azure and host workloads in a connected virtual network.
- **Disaster recovery**. Keep failover capacity in Azure and run critical workloads there if your primary site is unavailable.
- **Lift and shift migration**. Move existing server workloads with minimal application redesign.

**VM resources and sizing**
- size - number of processor cores, and amount of RAM
- storage disks - hard disk drives, solid state drives
- networking - virtual network, public IP address, and port configuration

**Scale and Resiliency**

1. Virtual Machine Scale Sets

	- **Definition:** Create and manage groups of identical, load-balanced VMs.
	- **Without Scale Sets:** Requires manual configuration management, utilization monitoring, and instance scaling.
    - **Key Benefits:**
	    - **Centralized Configuration:** Maintains configuration consistency automatically.
	    - **Autoscaling:** Automatically scales out/in based on demand or scheduled rules.
	    - **Load Balancing:** Integrates with load balancers for efficient traffic distribution.
    
2. Virtual Machine Availability Sets

- **Definition:** Improves VM-level resiliency inside a region to minimize downtime from maintenance or hardware failure.
- **Grouping Mechanisms:**
    - **Update Domain:** Group of VMs that can be rebooted together during planned maintenance.
    - **Fault Domain:** Group of VMs that share a common power and network failure point.
- **Key Considerations:**
    - Used for VM-level redundancy inside a region.
    - **Availability Zones** are preferred when supported for broader failure isolation.
    - **Cost:** Availability sets are free; you only pay for the VM instances.
