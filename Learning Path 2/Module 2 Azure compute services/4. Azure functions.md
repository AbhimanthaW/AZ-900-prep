event-driven, serverless compute option
- doesn’t require maintaining virtual machines or containers

build an app using VMs or containers, those resources have to be “running” in order for your app to function

an event wakes the function
- alleviating the need to keep resources provisioned when there are no events

**Benefits**

**Ideal Use Cases:**
- Triggered by events (REST APIs, timers, or messages from other Azure services)
- Quick-running workloads (executing within seconds or less)

**Auto-Scaling:** Dynamically scales in response to variable demand.
    
**Cost Efficiency:** Automatically deallocates resources when execution finishes, charging only for active **CPU time**.
    
**State Management:**
    - **Stateless (Default):** Functions restart fresh upon every event.
    - **Stateful (Durable Functions):** Tracks prior activity via context passed through execution.
        
**Deployment Flexibility:** Can be run as serverless or moved to non-serverless environments for custom scaling, virtual network integration, or complete isolation.
