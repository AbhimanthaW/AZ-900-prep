**Core Functions & Capabilities**

- **Site-to-Site (S2S):** Connects on-premises datacenters to Azure VNets
- **Point-to-Site (P2S):** Connects individual client devices directly to VNets
- **VNet-to-VNet:** Connects virtual networks to each other
- **Limits & Auth:** Strictly **1 VPN gateway per VNet** (can link to multiple endpoints); authentication relies on pre-shared keys

**Gateway Types**

- **Policy-Based:** Encrypts traffic by matching packets against static sets of source/destination IP ranges. Best for legacy devices or fixed IP configurations
    
- **Route-Based:** Preferred method. Uses IP routing (static/BGP) to model IPSec tunnels as virtual interfaces. Required for VNet-to-VNet, P2S, multisite connections, BGP, and ExpressRoute coexistence
    
**High Availability & Resiliency**

- **Active/Standby (Default):** Deploys two gateway instances where the standby takes over during failovers (planned failover takes seconds; unplanned takes ~90 seconds)
    
- **Active/Active:** Uses BGP and separate public IP addresses for both active instances to support redundant tunnels
    
- **ExpressRoute Failover:** Uses a VPN gateway over the public internet as a backup connection path if ExpressRoute experiences an outage
    
- **Zone-Redundant Gateways:** Deploys gateway instances across physical Availability Zones within supported regions using Standard public IPs
