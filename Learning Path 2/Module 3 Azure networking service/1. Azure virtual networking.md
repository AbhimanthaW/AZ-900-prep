Azure network = extension of on-premises network with resources that link other Azure resources

*Azure Virtual Networks (VNets) enable secure communication among Azure resources (VMs, Web Apps, AKS), the internet, and on-premises networks*

**Core Capabilities:**

  - **Isolation & Segmentation:** Define private IP address spaces (CIDR block). Divide VNets into Subnets. Use built-in Azure DNS or custom DNS servers
  - **Endpoints:**
      - **Public Endpoints:** Public IP address, accessible over the internet
      - **Private Endpoints:** Private IP from the VNet address space, isolated from the public internet
  - **Communication Types:**
      - **Between Azure Resources:** VNet integration (VMs, AKS) & Service Endpoints (Azure SQL, Storage)
      - **With On-Premises Networks:**
          - **Point-to-Site (P2S) VPN:** Individual client devices to VNet over encrypted internet
          - **Site-to-Site (S2S) VPN:** On-premises network gateway to Azure VPN Gateway over encrypted internet
          - **ExpressRoute:** Dedicated, private fiber connection (bypasses public internet)
  - **Traffic Routing:**
      - **Default Routing:** Automatic routing between subnets, connected VNets, and internet
      - **User-Defined Routes (UDR):** Custom route tables to control/override traffic flow
      - **BGP:** Dynamic route propagation via VPN Gateways or ExpressRoute
  - **Traffic Filtering:**
      - **Network Security Groups (NSGs):** Rule-based allow/block filtering by IP, port, and protocol
      - **Network Virtual Appliances (NVAs):** Specialized VMs for advanced functions (e.g., firewalls, WAN optimization)
  - **Network Peering:**
      - **VNet Peering:** Connects two VNets directly over the Microsoft backbone network (local or cross-region) without traversing the public internet
