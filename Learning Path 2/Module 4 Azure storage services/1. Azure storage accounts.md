**Overview**
- An **Azure storage account** provides a unique namespace for your Azure Storage data, accessible globally over **HTTP or HTTPS**.
- Data stored is secure, highly available, durable, and massively scalable.

**Storage Account Types & Services**

The account type you choose determines supported services, redundancy options, and performance profiles:

1. **Standard general-purpose v2:**
    - _Supported Services:_ Blob Storage (including Data Lake), Queue Storage, Table Storage, and Azure Files.
    - _Redundancy:_ Supports all options (LRS, GRS, RA-GRS, ZRS, GZRS, RA-GZRS).
    - _Use Case:_ Recommended for most general workloads.
        
2. **Premium block blobs:**
    - _Supported Services:_ Block blobs and append blobs.
    - _Redundancy:_ LRS, ZRS.
    - _Use Case:_ High transaction rates, smaller objects, or low storage latency requirements.
        
3. **Premium file shares:**
    - _Supported Services:_ Azure Files only (supports both SMB and NFS).
    - _Redundancy:_ LRS, ZRS.
    - _Use Case:_ High-scale or high-performance file shares.
        
4. **Premium page blobs:**
    - _Supported Services:_ Page blobs only.
    - _Redundancy:_ LRS.
    
**Naming Rules & Endpoints**

- **Naming Rules:**
    - Must be between **3 and 24 characters** long.
    - May contain **numbers and lowercase letters only**.
    - Must be **globally unique** within all of Azure.
        
- **Service Endpoint Formats:** (`https://<storage-account-name>.<service>.core.windows.net`)
    
    - **Blob Storage:** `.blob.core.windows.net`
    - **Data Lake Storage Gen2:** `.dfs.core.windows.net`
    - **Azure Files:** `.file.core.windows.net`
    - **Queue Storage:** `.queue.core.windows.net`
    - **Table Storage:** `.table.core.windows.net`
